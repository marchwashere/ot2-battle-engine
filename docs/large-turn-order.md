# Larger turn-order queues

The old Rust opening profile rejected totals above eight because it implemented only the native selection-sort leaf. A Step Ahead route trials with four players and five/six enemies exposed this restriction.

`combat::sort_order` now ports `OT2BattleEngine/include/ot2/native_order_sort.hpp`: midpoint partition, binary32 natural-log depth limit, selection leaves, and heap fallback. Equal-speed swaps are preserved. The general 64-actor state limit remains.

`data/source/native-order-large-fixtures.json` contains 325 orders generated by running the original native instruction fixture, not by the Rust implementation. Sizes 0 through 64 cover equal, ascending, descending, three-way ties, and mixed keys. Generator: `tools/native-order-oracle.cpp`, built with the older project's include/generated directories, MSVC C++17, x64. Its stdout is the fixture JSON. The native instruction fixture includes original SortWait code plus patched predicate/log/memory helpers; provenance is in the older project's `tests/native_order_sort_fixture.cjs` and `docs/action-orders.md`.

Additional integration coverage initializes four players with five/six enemies, traverses three safe A Step Ahead Defends, and checks the Escape adapter. This validates the simulator and native ordering; it is not a new retail battle trace.
